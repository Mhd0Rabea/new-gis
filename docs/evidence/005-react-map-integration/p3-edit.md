# دليل تحقق P3: التحرير المكاني

**التاريخ**: 2026-10-04  
**الطبقة المختبرة**: `Military_Bases`  
**مسار الكتابة**: React → NestJS → PostGIS، دون `WFS-T`

## دورة CRUD الحية

1. أُنشئ سجل اصطناعي مؤقت بالقيم `base_id=990001` و`base_name=Codex P3 Synthetic` بعد رسم `Point` على OpenLayers.
2. أعاد NestJS معلم GeoJSON بمعرف UUID، وعرضته لوحة التفاصيل مباشرة دون إعادة تحميل التطبيق.
3. عُدلت الخاصية إلى `Codex P3 Synthetic Updated` وظهر وقت `updated_at` الجديد.
4. فُتح تأكيد الحذف ثم حُذف السجل عبر `DELETE /api/features/Military_Bases/:id`.
5. أكد استعلام API بالفلتر `base_id:990001` أن `total=0` بعد التنظيف.

## مسار لوحة المفاتيح

- أُنشئ سجل اصطناعي ثانٍ بالقيمة `base_id=990002` باستخدام حقل `GeoJSON geometry (EPSG:4326)` بدل النقر على الخريطة.
- استُخدمت الهندسة `{"type":"Point","coordinates":[39,35]}` ونجح الحفظ.
- حُذف السجل بعد الاختبار، ولم تبق بيانات اختبارية.

## التحقق من الأخطاء والمسودة

- فشل أول طلب حي برسالة `Request validation failed` لأن الخادم لم يكن يحلل `application/geo+json` رغم اعتماده في OpenAPI.
- بقيت الهندسة والحقول داخل المسودة بعد الفشل، وهو السلوك المطلوب.
- عولج السبب بإضافة parser لـ`application/geo+json` في NestJS، وإضافة نفس الإعداد إلى تطبيق الاختبار.
- عُدّل اختبار التكامل ليرسل `Content-Type: application/geo+json`، ثم نجحت مجموعتا اختبارات التكامل (`4/4`).

## تحديث العرض

- بعد `POST` و`PATCH` و`DELETE` استُدعي refresh لمصادر WMS، وأُعيد تحميل عدد نتائج الطبقة النشطة من API.
- لم يحدث reload كامل لتطبيق React.
