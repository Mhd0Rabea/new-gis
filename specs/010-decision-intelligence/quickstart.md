# Quickstart: تحقق مركز القرار

## المتطلبات

- تشغيل API المحلي وواجهة GIS-Base.
- وجود طبقات PostGIS حقيقية رفعها المستخدم.
- يرفع المستخدم ملفات التحقق بنفسه؛ لا يتضمن المشروع ملفات نموذجية أو بيانات مولدة.

## صيغ الملفات المطلوبة

### التتبع — JSON

ملف يحوي مصفوفة `points`، ولكل نقطة: `longitude`, `latitude`, `timestamp`، واختياريًا `id`, `speed`, `risk`. تُقارن النقاط بطبقتي `Threat_Areas` و`Patrol_Routes` المرفوعتين، وتُستخرج إنذارات الخطر وتأخر التحديث وانخفاض الجاهزية.

### المؤشرات — JSON

ملف يحوي `metric` و`scope` و`period.start` و`period.end` ومصفوفة `values` من ثلاث قراءات رقمية حقيقية على الأقل.

### التغير — GeoTIFF

صورتان TIF/TIFF حقيقيتان متطابقتان في الأبعاد والإسقاط والامتداد. ينتج التحليل مناطق تغير GeoJSON في EPSG:4326 ويحفظها داخليًا في EPSG:32637.

## سيناريوهات التحقق

1. افتح مركز القرار وتحقق من ترتيب المخاطر وشرح العوامل المتاحة فقط.
2. تحقق من مقارنة ثلاثة مسارات وظهور سبب التوصية وحالة الطريق.
3. ارفع ملف التتبع وشغّل الجلسة، ثم تحقق من الإنذارات وأوقفها.
4. راجع إنذارًا مع ملاحظة، وأعد تحميل الصفحة للتحقق من بقائه في PostgreSQL.
5. ارفع ملف المؤشرات وتحقق من النطاق والفترة وخط الأساس والثقة والقيود.
6. ارفع صورتين GeoTIFF وتحقق من عدد مناطق التغير وهندستها.
7. راجع توقعًا ومرشح تغير مع ملاحظة، ثم تحقق من بقاء القرار بعد إعادة تشغيل API.
8. شغّل `npm run build` في `api` و`GIS-Base`، ثم `npm run test:contract` في `api`.

## نتيجة النجاح

لا يعتمد النظام أي نتيجة تلقائيًا، ولا ينشئ بيانات بديلة، وتبقى كل النتائج مرتبطة بملفات وطبقات رفعها المستخدم وبقرار مراجعة محفوظ.
