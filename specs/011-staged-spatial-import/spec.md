# مواصفة الميزة: الاستيراد المكاني المرحلي

**Feature Branch**: 011-staged-spatial-import
**Created**: 2026-10-11
**Status**: Draft
**Input**: تحويل استيراد الطبقات الحقيقية إلى مسار مرحلي آمن قبل اعتمادها في الطبقات التشغيلية.

## User Scenarios & Testing

### User Story 1 - رفع وفحص دفعة مكانية (Priority: P1)

يرفع المستخدم ملفًا مكانيًا حقيقيًا ويستلم معاينة للمعالم والحقول والهندسة ونظام الإحداثيات والدومينات دون تغيير البيانات التشغيلية.

**Why this priority**: يمنع الاستيراد الجزئي أو إدخال بيانات غير متوافقة.

**Independent Test**: رفع GeoJSON صالح يحوي قيم دومين نصية والتحقق من ظهور تقرير الفحص والتحويلات المقترحة مع بقاء الطبقة التشغيلية دون تغيير.

**Acceptance Scenarios**:

1. **Given** ملف صالح، **When** يرفعه المستخدم ويختار الطبقة، **Then** تنشأ دفعة مرحلية وتظهر أعداد المعالم الصالحة والتحذيرات والأخطاء.
2. **Given** قيمة عربية أو إنجليزية تطابق دومين ArcGIS، **When** تفحص، **Then** يعرض النظام الرمز المعتمد قبل الاعتماد.
3. **Given** ملف أو هندسة غير صالحة، **When** تفحص، **Then** لا يتغير أي سجل تشغيلي وتظهر رسالة عربية واضحة.

### User Story 2 - مراجعة التكرارات والمطابقة (Priority: P2)

يراجع المستخدم الحقول والتكرارات ويختار لكل تطابق: تجاهل أو تحديث أو إنشاء جديد.

**Why this priority**: يحمي البيانات من النسخ المكررة والتحديث غير المقصود.

**Independent Test**: رفع معلم يحمل source_id موجودًا، ومعلم بلا معرف له الاسم نفسه ويقع ضمن 25 مترًا، والتحقق من تصنيفهما وطلب قرار المستخدم.

**Acceptance Scenarios**:

1. **Given** معلم يطابق source_id قائمًا، **When** تظهر المراجعة، **Then** يصنف كتطابق مؤكد.
2. **Given** غياب source_id وتطابق الاسم والقرب ضمن 25 مترًا، **When** تظهر المراجعة، **Then** يصنف كتطابق محتمل دون تحديث تلقائي.
3. **Given** أخطاء مانعة، **When** يحاول المستخدم الاعتماد، **Then** تمنع العملية وتحدد المعالم المطلوب إصلاحها أو استبعادها.

### User Story 3 - اعتماد ذري وقابل للتدقيق (Priority: P3)

يعتمد المستخدم الدفعة المقبولة كاملة ويحصل على نتيجة موثقة بلا استيراد جزئي.

**Why this priority**: يثبت PostGIS كمصدر الحقيقة ويحفظ أثر كل تغيير.

**Independent Test**: اعتماد دفعة والتحقق من تطبيق جميع القرارات أو التراجع عنها كاملة عند فشل أي معلم، مع إنشاء سجل تدقيق.

**Acceptance Scenarios**:

1. **Given** دفعة بلا أخطاء وقرارات مكتملة، **When** تعتمد، **Then** تطبق الإضافات والتحديثات ضمن عملية واحدة.
2. **Given** فشل أثناء الاعتماد، **When** تنتهي المحاولة، **Then** لا يبقى أي تغيير جزئي.
3. **Given** دفعة منتهية، **When** يفتح سجلها، **Then** يرى الملف والطبقة والتوقيت والأعداد والقرارات والنتيجة.

### Edge Cases

- ملف فارغ أو كبير أو يحوي أنواع هندسة مختلطة.
- ملف دون CRS أو بإحداثيات خارج النطاق أو بترتيب خاطئ.
- أسماء حقول ArcGIS أو اختلاف حالة الأحرف.
- قيم دومين عربية أو إنجليزية أو رموز غير معتمدة.
- أكثر من تطابق محتمل أو تغير السجل بعد الفحص وقبل الاعتماد.
- إعادة رفع الملف نفسه أو إعادة اعتماد دفعة منتهية.

## Requirements

### Functional Requirements

- **FR-001**: MUST يحفظ كل رفع كدفعة مرحلية دون تعديل الطبقات التشغيلية.
- **FR-002**: MUST يدعم GeoJSON أولًا مع عقد توسع لـGeoPackage وShapefile المضغوط.
- **FR-003**: MUST يفحص الهندسة وCRS والإحداثيات والحقول المطلوبة وأنواع القيم وحدودها.
- **FR-004**: MUST يطابق الأسماء canonical وأسماء ArcGIS والأسماء الفيزيائية مركزيًا.
- **FR-005**: MUST يحول قيم الدومين العربية والإنجليزية إلى الرموز المعتمدة ويعرض التحويل.
- **FR-006**: MUST يحفظ source_id الاختياري واسم المصدر مع معرف داخلي مستقل.
- **FR-007**: MUST يكتشف التكرار المؤكد عبر source_id ضمن المصدر والطبقة.
- **FR-008**: MUST يكتشف التكرار المحتمل بالاسم والقرب ضمن 25 مترًا عند غياب source_id.
- **FR-009**: MUST يتيح create وupdate وskip دون تحديث تلقائي.
- **FR-010**: MUST يمنع الاعتماد عند وجود أخطاء مانعة أو تكرارات بلا قرار.
- **FR-011**: MUST ينفذ الاعتماد كعملية ذرية بلا نتائج جزئية.
- **FR-012**: MUST يعيد التحقق لحظة الاعتماد لمنع الكتابة فوق تغيير أحدث.
- **FR-013**: MUST يسجل الملف والطبقة والمصدر والتوقيت والأعداد والقرارات والنتيجة.
- **FR-014**: MUST يسمح برفض الدفعة أو حذفها قبل الاعتماد وإعادة فحصها.
- **FR-015**: MUST يوفر تقرير أخطاء قابلًا للتنزيل يحدد المعلم والحقل والقيمة والسبب والشدة.
- **FR-016**: MUST يعرض الرسائل وأسماء الحقول بالعربية والقيم التقنية ككود عند الحاجة.
- **FR-017**: MUST يحافظ على GeoJSON الخارجي في EPSG:4326 والتخزين في EPSG:32637.
- **FR-018**: MUST لا يولد معالم أو قيمًا مكانية بديلة عند نقص بيانات المستخدم.

- **FR-019**: MUST تكون PostGIS نقطة البيانات المشتركة بين ArcGIS Pro وMGOS وGeoServer دون مزامنة ملفات ثنائية.
- **FR-020**: MUST تتضمن السجلات التشغيلية رقم إصدار ومحررًا أخيرًا ووقت تحديث يعمل مع تعديلات ArcGIS Pro وMGOS.
- **FR-021**: MUST يرفض MGOS تحديث نسخة أقدم إذا تغير السجل بعد قراءته ويطلب إعادة تحميله.
- **FR-022**: MUST توثق أدوار اتصال ArcGIS Pro للقراءة والتحرير دون منح صلاحيات مالك المخطط.
### Key Entities

- **Import Batch**: ملف وطبقة ومصدر وحالة وملخص الفحص.
- **Staged Feature**: هندسة وخصائص أصلية ومطبّعة ونتيجة تحقق.
- **Validation Issue**: خطأ أو تحذير مرتبط بمعلم وحقل.
- **Duplicate Match**: تطابق مؤكد أو محتمل مع سجل تشغيلي.
- **Import Decision**: إنشاء أو تحديث أو تجاهل مع المراجع والتوقيت.
- **Import Audit Record**: ملخص محاولة الاعتماد ونتيجتها.

## Success Criteria

### Measurable Outcomes

- **SC-001**: لا تتغير الطبقات التشغيلية في 100% من عمليات الرفع والفحص قبل الاعتماد.
- **SC-002**: تعرض خلاصة فحص 10,000 معلم خلال 60 ثانية محليًا.
- **SC-003**: يمنع 100% من الاعتمادات التي تحوي أخطاء مانعة أو قرارات ناقصة.
- **SC-004**: تنتهي كل محاولة اعتماد إما بتطبيق كامل أو بصفر تغييرات.
- **SC-005**: يمكن تتبع كل معلم مضاف أو محدث إلى دفعة وملف وقرار.
- **SC-006**: يستورد ملف القواعد العسكرية الحالي ذي 12 معلمًا دون تعديل يدوي للدومينات.

## Assumptions

- PostGIS هو المصدر الوحيد للحقيقة بعد الاعتماد.
- ArcGIS Pro وQGIS للتجهيز المتقدم، والمراجعة والاعتماد من MGOS.
- source_id فريد ضمن المصدر والطبقة.
- 25 مترًا قاعدة أولية قابلة للضبط ولا تؤدي لتحديث تلقائي.
- الإصدار الأول يستخدم هوية المراجع المتاحة حاليًا أو هوية محلية موثقة.
