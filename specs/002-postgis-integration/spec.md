# Feature Specification: PostGIS Integration

**Feature Branch**: `002-postgis-integration`

**Created**: 2026-10-03

**Status**: Implemented — Verified

**Input**: نقل نموذج MGOS من File Geodatabase إلى PostgreSQL/PostGIS محلي مع الحفاظ على الأسماء والعلاقات الأساسية.

## User Scenarios & Testing

### User Story 1 - التحقق من البيئة المحلية (Priority: P1)

كمطور، أريد إثبات أن PostgreSQL وPostGIS واتصال ArcGIS Pro تعمل قبل نقل البيانات كي لا أغيّر بيئة سليمة أو أبني على توافق مفترض.

**Why this priority**: يمنع التثبيت غير الضروري ويكشف مشكلة التوافق مبكرًا.

**Independent Test**: الاتصال بقاعدة تدريب، تفعيل PostGIS، وعرض طبقة اختبار مكانية من ArcGIS Pro.

**Acceptance Scenarios**:

1. **Given** PostgreSQL المحلي يعمل، **When** تُفحص قاعدة `mgos`، **Then** يظهر إصدار PostGIS الفعلي وتنجح دالة مكانية بسيطة.
2. **Given** بيانات اختبار مكانية، **When** يتصل ArcGIS Pro، **Then** يعرض الجدول بهندسته وCRS الصحيحين أو يسجل مسار النقل الاحتياطي.

---

### User Story 2 - نقل النواة والتحقق منها (Priority: P2)

كمطور، أريد نقل الطبقات والجداول الأساسية إلى PostGIS مع معرفات وعلاقات وفهارس صحيحة كي تصبح مصدر بيانات الويب.

**Why this priority**: يثبت التحويل على نطاق صغير قبل التوسعة.

**Independent Test**: مقارنة عدد السجلات والمعرفات والهندسات للطبقات الأربع والجداول الثلاثة بين المصدر والوجهة.

**Acceptance Scenarios**:

1. **Given** نواة ArcGIS مكتملة، **When** تُنقل، **Then** تتطابق الأسماء والأنواع والأعداد ولا توجد هندسات غير صالحة.
2. **Given** علاقات النواة، **When** تُفحص المفاتيح الأجنبية، **Then** لا توجد سجلات يتيمة.

---

### User Story 3 - إكمال مخزن النشر (Priority: P3)

كمطور، أريد نقل بقية المخطط وتوثيق الفروق عن File Geodatabase كي يكون PostGIS جاهزًا لـGeoServer وNestJS.

**Why this priority**: التوسعة تعتمد على نجاح مسار النواة.

**Independent Test**: تشغيل تقرير مقارنة كامل وفحص الوصول بحساب تطبيق غير إداري.

**Acceptance Scenarios**:

1. **Given** نجاح نقل النواة، **When** يكتمل النقل، **Then** تتوفر جميع الطبقات والجداول المسموح بنشرها.
2. **Given** حساب التطبيق، **When** يقرأ ويكتب بيانات مسموحة، **Then** تنجح العمليات دون امتلاك صلاحيات إدارة الخادم.

---

### User Story 4 - نقل المشروع إلى بيئة أخرى (Priority: P4)

كمطور، أريد نسخ المشروع إلى مسار أو جهاز آخر وتجهيز اتصالاته المحلية دون تعديل المصدر، كي أتمكن من مشاركته وإعادة استخدامه بأمان.

**Why this priority**: يضمن أن نتيجة التعلم قابلة للمشاركة بعد اكتمال مسار النقل الأساسي، دون ربط المشروع بجهاز واحد.

**Independent Test**: نسخ المشروع إلى مسار مختلف، توفير اتصال محلي جديد، ثم التحقق من جاهزية البيئة وتشغيل النقل التجريبي دون الرجوع إلى أي مسار من الجهاز الأصلي.

**Acceptance Scenarios**:

1. **Given** نسخة المشروع في مسار جديد والمكونات المطلوبة متاحة، **When** تُفحص البيئة، **Then** تُكتشف المكونات والملفات المحلية أو تظهر قائمة دقيقة بما ينقص دون تثبيت تلقائي.
2. **Given** ملف اتصال محلي صالح في البيئة الجديدة، **When** يُشغّل النقل التجريبي، **Then** ينجح دون تعديل ملفات المصدر أو الاعتماد على مسار مطلق من البيئة السابقة.

### Edge Cases

- PostGIS مثبت على الخادم لكنه غير مفعّل في قاعدة `mgos`.
- ArcGIS Pro لا يتصل بإصدار PostgreSQL الحالي.
- اختلاف حالة الأحرف أو طول أسماء الحقول.
- فشل تحويل GUID أو Date أو Domain.
- هندسة بلا SRID أو بنوع مخالف للطبقة.
- وجود أكثر من File Geodatabase أو ملف اتصال مرشح للاكتشاف التلقائي.
- تثبيت الأدوات في مسارات مختلفة عن الجهاز الأصلي.
- نسخ المشروع دون ملف الاتصال المحلي المستبعد من المشاركة.

## Requirements

### Functional Requirements

- **FR-001**: MUST فحص PostgreSQL وPostGIS والخدمة المحلية قبل أي تثبيت أو تغيير.
- **FR-002**: MUST إنشاء أو إعادة استخدام قاعدة `mgos` وتفعيل PostGIS فيها.
- **FR-003**: MUST إثبات اتصال ArcGIS Pro `3.7.1 Standard` بـPostgreSQL `18.6` باختبار صغير قبل النقل.
- **FR-004**: MUST استخدام مسار ArcGIS Pro للنقل عند نجاح الاختبار، واستخدام `ogr2ogr` فقط كخيار احتياطي موثق.
- **FR-005**: MUST الحفاظ على الأسماء القانونية كأسماء Canonical خارجية، مع mapping موثق إلى أسماء PostgreSQL الفيزيائية lowercase المطلوبة لتوافق ArcGIS.
- **FR-006**: MUST تخزين الهندسات في `EPSG:32637` مع قيد نوع هندسة لكل طبقة.
- **FR-007**: MUST تحويل `GlobalID` وGUID إلى UUID ثابت لا يتغير أثناء النقل المتكرر.
- **FR-008**: MUST إنشاء مفاتيح أساسية وأجنبية وفهارس مكانية للنواة ثم التوسعة.
- **FR-009**: MUST توثيق تحويل Domains وRelationship Classes إلى قيود وجداول مرجعية أو مفاتيح أجنبية.
- **FR-010**: MUST توفير نقل قابل لإعادة التشغيل دون تكرار السجلات.
- **FR-011**: MUST مقارنة الأعداد والمعرفات وSRID وصحة الهندسات بعد كل نقل.
- **FR-012**: MUST استخدام حساب تطبيق محدود وعدم وضع كلمات المرور في المستودع.
- **FR-013**: MUST NOT تحويل PostgreSQL إلى Enterprise Geodatabase ضمن هذا المسار.
- **FR-014**: MUST تمكين نقل المشروع إلى مسار أو جهاز آخر دون تعديل المصدر، عبر إعدادات محايدة للجهاز واكتشاف آمن أو قيم محلية صريحة، مع إبقاء الأسرار وملفات الاتصال المحلية خارج المشاركة.

### Key Entities

- **Database**: قاعدة `mgos` المحلية المفعّل فيها PostGIS.
- **Spatial Table**: تمثيل PostGIS لطبقة ArcGIS مع UUID وGeometry وSRID.
- **Reference Constraint**: بديل Domain والعلاقة في قاعدة البيانات.
- **Migration Run**: عملية نقل لها مصدر ووقت ونتيجة مقارنة.

## Success Criteria

### Measurable Outcomes

- **SC-001**: ينجح فحص PostgreSQL وPostGIS والاتصال أو ينتج قرار fallback واضحًا قبل نقل أي بيانات.
- **SC-002**: تتطابق أعداد سجلات النواة والمعرفات بنسبة 100% بعد النقل.
- **SC-003**: تكون 100% من هندسات الاختبار صالحة وتحمل `SRID 32637`.
- **SC-004**: لا توجد مفاتيح أجنبية يتيمة في عينة التحقق.
- **SC-005**: يمكن إعادة النقل مرتين دون مضاعفة عدد السجلات.
- **SC-006**: بعد نقل المشروع إلى مسار مختلف، تنجح 100% من فحوص المرحلة المطلوبة والنقل التجريبي دون أي مرجع إلى مسار مطلق من البيئة السابقة أو تعديل لملفات المصدر.

## Assumptions

- خدمة PostgreSQL `18.6` تعمل محليًا.
- ملفات PostGIS `3.6.2` مثبتة، وتفعيلها داخل القاعدة يحتاج تحققًا.
- لا يستخدم Docker.
- بيانات ArcGIS Foundation هي المصدر في هذه المرحلة.
