# خطة المرحلة 007: المعالجة المكانية المتقدمة

## الملخص

إضافة وحدة processing داخل NestJS لإدارة الملفات والمهام المحلية، ومحول أدوات command-line بقوائم سماح، ثم صفحات React لمركز المعالجة والعرض ثلاثي الأبعاد. يبدأ التنفيذ بتدفق مهام صغير ومخزن محلي قابل للتهيئة، ثم Raster/DEM، ثم سحابات النقاط، ثم 3D.

## بوابة الأدوات

قبل التنفيذ يجب تشغيل فحص read-only لتحديد وجود وإصدارات GDAL وPDAL ودعم WebGL. لا يُثبّت أي برنامج ولا مكتبة واجهة ثقيلة قبل عرض نتيجة الفحص والحصول على موافقة صريحة.

## قرارات معمارية أولية

- تبقى الخدمة ضمن تطبيق NestJS الحالي بوحدة processing واحدة.
- بيانات المهمة الوصفية في PostgreSQL؛ الملفات في مجلد بيئي خارج Git.
- التنفيذ غير المتزامن يبدأ بطابور محلي محدود التوازي، بلا Redis أو خدمة جديدة.
- الأدوات الخارجية لا تتلقى نصوص أو أوامر حرة؛ كل عملية ومعامل ضمن allowlist.
- تحديث الحالة عبر polling بسيط أولاً؛ لا WebSocket في النسخة الأولى.
- العرض الثلاثي الأبعاد يختار بعد فحص البيئة بين مكتبة مناسبة أو حل أخف.

## مراحل التنفيذ

1. فحص الأدوات والعينات والأمان.
2. عقد الملفات والمهام وواجهات API.
3. مركز المعالجة وحالات المهمة.
4. Raster وDEM والمخرجات.
5. سحابات النقاط وDEM.
6. العرض ثلاثي الأبعاد والبديل 2D.
7. اختبارات التكامل والأداء والتنظيف والتوثيق.

## فحص الدستور

- PASS: البيانات تدريبية فقط.
- PASS: AI يبقى مؤجلاً.
- PASS: لا تثبيت قبل الفحص والموافقة.
- PASS: الإعدادات والمسارات خارج المصدر.
- PASS: لا خدمة إضافية قبل إثبات الحاجة.
